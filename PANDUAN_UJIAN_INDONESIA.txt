1. PENGENALAN MVVM ARCHITECTURE
═══════════════════════════════════════════════════════════════════════════════════

APA ITU MVVM?
════════════
MVVM = Model - View - ViewModel

┌─────────────────────────────────────────────────────────────────┐
│ VIEW (UI)                                                       │
│ ├─ Composable (Jetpack Compose)                                │
│ ├─ XML Layouts                                                 │
│ └─ User Interface                                              │
└────────────────┬────────────────────────────────────────────────┘
                 │ Observe (StateFlow)
                 │ Listen untuk changes
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ VIEWMODEL                                                       │
│ ├─ Business Logic                                              │
│ ├─ State Management (StateFlow)                                │
│ ├─ Coroutines untuk async operations                           │
│ └─ Repository access                                           │
└────────────────┬────────────────────────────────────────────────┘
                 │ Call methods
                 │ Trigger operations
                 ▼
┌─────────────────────────────────────────────────────────────────┐
│ MODEL / REPOSITORY                                              │
│ ├─ Data Layer (Database, API calls)                            │
│ ├─ Business rules                                              │
│ └─ Data transformation                                         │
└─────────────────────────────────────────────────────────────────┘

ALUR KERJA:
1. User interact dengan UI (klik button, ketik text)
2. View call ViewModel method
3. ViewModel process logic, interact dengan Repository/Database
4. Data di-update di StateFlow
5. View observe StateFlow, UI update otomatis (reactive)

KEUNTUNGAN MVVM:
✓ Separation of concerns (pisah tanggungjawab)
✓ Testable (bisa di-test dengan mudah)
✓ Reusable (bisa pakai ViewModel di multiple views)
✓ Reactive (UI otomatis update saat data berubah)

2. STATEFLOW & COROUTINES
═══════════════════════════════════════════════════════════════════════════════════

APA ITU STATEFLOW?
══════════════════
StateFlow = State Management dengan reactive pattern

Analogi: Bayangkan WhatsApp notification
- Saat ada pesan baru, notification langsung muncul
- Kamu tidak perlu cek berkali-kali
- StateFlow work sama seperti itu

CONTOH BASIC:
─────────────
// Private (ViewModel saja bisa ubah)
private val _journals = MutableStateFlow<List<Journal>>(emptyList())

// Public (UI bisa observe/baca)
val journals: StateFlow<List<Journal>> = _journals.asStateFlow()

// Gimana cara observe di UI?
val journals by viewModel.journals.collectAsState(initial = emptyList())

// Gimana UI auto update?
LaunchedEffect(journals) {
    // Setiap kali journals berubah, code ini dijalankan
    android.util.Log.d("JournalListScreen", "Journals updated: ${journals.size} items")
}

FLOW PATTERN:
─────────────
private val _value = MutableStateFlow(initialValue)
val value: StateFlow<...> = _value.asStateFlow()

WHY "private" dan "public"?
- Private: Cegah UI langsung ubah state (harus lewat ViewModel method)
- Controlled changes: Biar ViewModel bisa validate dulu sebelum update


APA ITU COROUTINES?
═══════════════════
Coroutines = Lightweight threads untuk async operations (non-blocking)

Tanpa Coroutines (BLOCKING - BAD ❌):
────────────────────────────────────
fun fetchJournals() {
    val journals = api.getJournals()  // Block UI untuk 2 detik!
    _journals.value = journals         // UI freeze, user can't click anything
}

Dengan Coroutines (NON-BLOCKING - GOOD ✅):
──────────────────────────────────────────
fun fetchJournals() {
    viewModelScope.launch {  // Start coroutine
        val journals = api.getJournals()  // Network call (2 detik)
        _journals.value = journals         // Update state
        // UI tetap responsive! User bisa interact sambil menunggu
    }
}

VIEWMODELSCOPE.LAUNCH:
─────────────────────
viewModelScope = Coroutine scope yang tied ke ViewModel lifecycle

Keuntungan:
- Auto cancel coroutine saat ViewModel destroyed
- Prevent memory leak
- Safe untuk UI updates

CONTOH REAL (dari Journal Feature):
───────────────────────────────────
fun addJournal(userId: Int, content: String, mood: MoodType, onComplete: () -> Unit = {}) {
    _isSaving.value = true  // Show loading state
    
    viewModelScope.launch {  // Non-blocking coroutine
        val request = JournalRequest(
            user_id = userId,
            content = content,
            mood = mood.name.lowercase()  // lowercase untuk API
        )

        journalRepository.createJournal(request)
            .onSuccess {
                android.util.Log.d("JournalVM", "Journal created successfully")
                fetchJournals(userId)  // Refresh list
                _isSaving.value = false  // Hide loading
                onComplete()  // Callback ke screen
            }
            .onFailure { e ->
                android.util.Log.e("JournalVM", "Add failed: ${e.message}")
                _isSaving.value = false
            }
    }
}

BREAKDOWN:
- _isSaving.value = true → Button disabled, show loading spinner
- viewModelScope.launch → Non-blocking coroutine
- journalRepository.createJournal → API call (auto happens in background)
- onSuccess → Update list, hide loading, callback
- onFailure → Handle error

4. CODE CORRECTNESS & BEST PRACTICES
═══════════════════════════════════════════════════════════════════════════════════

ERROR YANG KAMU ENCOUNTER & SOLUSINYA:
════════════════════════════════════════

❌ MASALAH #1: Journal screen blank
─────────────────────────────────────
Problem: userIdValue = null
Root Cause: userId tidak di-restore saat app restart
Solution: Update AuthViewModel.checkLoginStatus() untuk restore userId dari TokenManager

Pelajaran:
- State persistence penting untuk session management
- onCreate() dipanggil saat app start, harus restore semua state
- Jangan asumsi userId always ada

CODE:
private fun checkLoginStatus() {
    viewModelScope.launch {
        authRepository.isLoggedIn().collect { isLoggedIn ->
            _isLoggedIn.value = isLoggedIn
            if (isLoggedIn) {
                // PENTING: Restore userId dari saved token
                authRepository.getCurrentUserId().collect { userId ->
                    _userId.value = userId
                }
            }
        }
    }
}


❌ MASALAH #2: Journal entry blank saat buat baru
──────────────────────────────────────────────────
Problem: Text dari entry sebelumnya masih ada
Root Cause: LaunchedEffect(currentJournal) terus overwrite state
Solution: Add condition isEditMode, hanya restore saat edit mode

Pelajaran:
- LaunchedEffect(dependency) dipanggil setiap kali dependency berubah
- Harus careful dengan logic di LaunchedEffect
- Conditional execution important

CODE:
LaunchedEffect(journalId) {
    if (journalId == null) {
        // CREATE mode: Reset ke default
        selectedMood = MoodType.HAPPY
        content = ""
    } else {
        // EDIT mode: Load dari API
        viewModel.loadJournal(journalId)
    }
}


❌ MASALAH #3: Mood selection tidak berubah
────────────────────────────────────────────
Problem: Klik mood button, moodnya tidak update di UI
Root Cause: API return lowercase ("tired"), tapi code compare dengan uppercase ("TIRED")
Solution: Convert ke uppercase sebelum parse enum

Pelajaran:
- Case sensitive! "TIRED" ≠ "tired"
- API dan enum harus consistent
- Gunakan .uppercase() / .lowercase() untuk normalize

CODE:
selectedMood = try {
    MoodType.valueOf(currentJournal!!.mood.uppercase())  // ← .uppercase() penting!
} catch (e: Exception) {
    MoodType.HAPPY
}


❌ MASALAH #4: Entry masuk ke API, tapi tidak muncul di list
────────────────────────────────────────────────────────────
Problem: Saat addJournal berhasil, navigasi kembali tapi list masih kosong
Root Cause: navigasi terjadi SEBELUM fetchJournals() selesai
Solution: Gunakan onComplete callback, navigasi HANYA setelah API semua selesai

Pelajaran:
- Async operations tidak instant
- Jangan asumsi data sudah update sebelum callback
- Gunakan callback untuk sequencing operations

CODE (SEBELUM - WRONG):
if (content.isNotEmpty()) {
    viewModel.addJournal(userId, content, mood)
    onSaved()  // ❌ Called immediately, before API finishes!
}

CODE (SESUDAH - CORRECT):
if (content.isNotEmpty()) {
    viewModel.addJournal(
        userId, content, mood,
        onComplete = { onSaved() }  // ✅ Called after API + refresh completes
    )
}


❌ MASALAH #5: JWT expired, semua API calls fail
─────────────────────────────────────────────────
Problem: Access token dari kemarin sudah expired (1 hour)
Root Cause: Token hanya valid 1 jam, tidak ada refresh mechanism
Solution: Implement refresh token dengan TokenRefreshInterceptor

Pelajaran:
- Token expiration adalah security feature
- Tidak boleh extend token expiration terlalu panjang
- Implement refresh token untuk seamless UX
- Interceptor pattern bagus untuk auto-handling


BEST PRACTICES CHECKLIST:
═════════════════════════

✓ NAMING:
  - StateFlow names: private _state, public state
  - Methods: verb + noun (fetchJournals, addJournal, deleteJournal)
  - Variables: camelCase (isSaving, currentJournal)

✓ STATE MANAGEMENT:
  - Don't expose MutableStateFlow publicly
  - Use immutable return type StateFlow
  - Only ViewModel modifies state

✓ ERROR HANDLING:
  - Try-catch untuk parsing (enum.valueOf)
  - Log errors dengan timestamp
  - Show user-friendly error messages

✓ LOGGING:
  - Debug log untuk normal flow
  - Error log untuk exceptions
  - Tag dengan screen/class name

✓ ASYNC OPERATIONS:
  - Use viewModelScope.launch
  - Don't block UI thread
  - Use callbacks untuk sequencing

✓ TESTING MINDSET:
  - Each method should have single responsibility
  - Dependencies injected (not hardcoded)
  - Logic testable without UI

NavHost(navController, startDestination) {

        const result = await UserService.login(req.body)

static async login(body: any) {
    // Query: SELECT * FROM users WHERE username = ?
    const user = await prisma.user.findUnique({
        where: { username: body.username }
    })
    
    if (!user) {
        throw new Error("User not found")
    }
    
    // Compare password
    const isPasswordValid = await bcrypt.compare(body.password, user.password)
    
    if (!isPasswordValid) {
        throw new Error("Password invalid")
    }
    
    return user
}

class JournalViewModel(
    private val journalRepository: JournalRepository
) : ViewModel() {

    // STATE: List of journals
    private val _journals = MutableStateFlow<List<Journal>>(emptyList())
    val journals: StateFlow<List<Journal>> = _journals.asStateFlow()

    // STATE: Single journal for editing
    private val _currentJournal = MutableStateFlow<Journal?>(null)
    val currentJournal: StateFlow<Journal?> = _currentJournal.asStateFlow()

    // STATE: Loading indicator
    private val _isSaving = MutableStateFlow(false)
    val isSaving: StateFlow<Boolean> = _isSaving.asStateFlow()

    // FETCH JOURNALS - Called when screen loads
    fun fetchJournals(userId: Int) {
        viewModelScope.launch {
            journalRepository.getJournals(userId)
                .onSuccess { journals ->
                    _journals.value = journals
                    Log.d("JournalVM", "Fetched ${journals.size} journals")
                }
                .onFailure { e ->
                    Log.e("JournalVM", "Fetch failed: ${e.message}")
                }
        }
    }

    // LOAD SINGLE JOURNAL - For edit mode
    fun loadJournal(journalId: Int) {
        _currentJournal.value = null
        viewModelScope.launch {
            journalRepository.getJournal(journalId)
                .onSuccess { journal ->
                    _currentJournal.value = journal
                }
                .onFailure { e ->
                    Log.e("JournalVM", "Load failed: ${e.message}")
                }
        }
    }

    // ADD NEW JOURNAL
    fun addJournal(
        userId: Int,
        content: String,
        mood: MoodType,
        onComplete: () -> Unit = {}
    ) {
        _isSaving.value = true  // Show loading
        viewModelScope.launch {
            val request = JournalRequest(
                user_id = userId,
                content = content,
                mood = mood.name.lowercase()  // API expects lowercase
            )

            journalRepository.createJournal(request)
                .onSuccess {
                    Log.d("JournalVM", "Journal created successfully")
                    fetchJournals(userId)  // Refresh list
                    _isSaving.value = false  // Hide loading
                    onComplete()  // Callback to screen
                }
                .onFailure { e ->
                    Log.e("JournalVM", "Add failed: ${e.message}")
                    _isSaving.value = false
                }
        }
    }

    // UPDATE JOURNAL
    fun updateJournal(
        journalId: Int,
        userId: Int,
        content: String,
        mood: MoodType,
        onComplete: () -> Unit = {}
    ) {
        _isSaving.value = true
        viewModelScope.launch {
            val request = JournalUpdateRequest(
                content = content,
                mood = mood.name.lowercase()
            )

            journalRepository.updateJournal(journalId, request)
                .onSuccess {
                    Log.d("JournalVM", "Journal updated successfully")
                    fetchJournals(userId)
                    _isSaving.value = false
                    onComplete()
                }
                .onFailure { e ->
                    Log.e("JournalVM", "Update failed: ${e.message}")
                    _isSaving.value = false
                }
        }
    }

    // DELETE JOURNAL - Optimistic delete
    fun deleteJournal(journalId: Int, userId: Int) {
        // Remove dari UI immediately
        _journals.value = _journals.value.filter { it.journal_id != journalId }
        
        viewModelScope.launch {
            journalRepository.deleteJournal(journalId)
                .onSuccess {
                    Log.d("JournalVM", "Journal deleted successfully")
                }
                .onFailure { e ->
                    Log.e("JournalVM", "Delete failed: ${e.message}")
                    // Reload if delete fails to restore item
                    fetchJournals(userId)
                }
        }
    }
}

PELAJARAN DARI CODE INI:
- Selalu ada 3 state: loading, success, failure
- onComplete callback untuk navigation flow control
- Lowercase untuk API consistency
- Log dengan tag dan message yang descriptive

@Composable
fun JournalEntryScreen(
    viewModel: JournalViewModel,
    userId: Int,
    journalId: Int?,
    onBack: () -> Unit,
    onSaved: () -> Unit
) {
    var selectedMood by remember { mutableStateOf(MoodType.HAPPY) }
    var content by remember { mutableStateOf("") }

    val isEditMode = journalId != null
    val currentJournal by viewModel.currentJournal.collectAsState(initial = null)
    val isSaving by viewModel.isSaving.collectAsState()

    // Reset fields when switching modes
    LaunchedEffect(journalId) {
        if (journalId == null) {
            // CREATE mode: Reset
            selectedMood = MoodType.HAPPY
            content = ""
        } else {
            // EDIT mode: Load from API
            viewModel.loadJournal(journalId)
        }
    }

    // Update fields when journal loaded
    LaunchedEffect(currentJournal) {
        if (currentJournal != null && isEditMode) {
            content = currentJournal!!.content
            selectedMood = try {
                MoodType.valueOf(currentJournal!!.mood.uppercase())
            } catch (e: Exception) {
                MoodType.HAPPY
            }
        }
    }

    // UI Code
    Box(modifier = Modifier.fillMaxSize()) {
        // ... Background image, etc
        
        Column {
            Row {
                Icon(...) { onBack() }  // Back button
                
                Text(if (isEditMode) "Update" else "Save") {
                    if (content.isNotEmpty()) {
                        if (isEditMode && journalId != null) {
                            // EDIT
                            viewModel.updateJournal(
                                journalId,
                                userId,
                                content,
                                selectedMood,
                                onComplete = { onSaved() }
                            )
                        } else {
                            // CREATE
                            viewModel.addJournal(
                                userId,
                                content,
                                selectedMood,
                                onComplete = { onSaved() }
                            )
                        }
                    }
                }
            }
            
            // Mood buttons
            MoodRow(selectedMood) { selectedMood = it }
            
            // Text input
            TextInput(content) { content = it }
        }
    }
}

PELAJARAN:
- Separate LaunchedEffect untuk different concerns
- collectAsState() untuk observe StateFlow
- Callback passing untuk flow control

static async login(req: Request, res: Response, next: NextFunction) {
    try {
        // 1. Authenticate user (username + password)
        const result = await UserService.login(req.body)

        // 2. Generate tokens
        const accessToken = generateAccessToken({
            user_id: result.user_id,
            username: result.username
        })
        const refreshToken = generateRefreshToken({
            user_id: result.user_id,
            username: result.username
        })

        // 3. Send response
        res.status(200).json({
            accessToken,      // Valid for 1 hour
            refreshToken,     // Valid for 7 days
            user: result
        })
    } catch (error) {
        next(error)
    }
}

static async refreshToken(req: Request, res: Response, next: NextFunction) {
    try {
        // 1. Get refresh token from request
        const { refreshToken } = req.body

        // 2. Verify refresh token
        const payload = verifyToken(refreshToken)

        // 3. Generate new access token
        const newAccessToken = generateAccessToken({
            user_id: payload.user_id,
            username: payload.username
        })

        // 4. Send response
        res.status(200).json({
            accessToken: newAccessToken  // New 1 hour token
        })
    } catch (error) {
        next(error)  // 401 if refresh token invalid
    }
}

PELAJARAN:
- Separate short-lived (accessToken) dan long-lived (refreshToken)
- Refresh endpoint stateless (tidak perlu check database)
- Token verification auto-happen saat verifyToken()
